# セーフクリーナー

ROOT、Shizuku、ADB、shell コマンドを使わず、Android の設定画面をユーザー補助サービスで操作して、ユーザーがインストールしたアプリの「キャッシュのみ削除」と「強制停止」を順番に実行する Android アプリです。処理中は設定画面が前面に表示され、どの操作が行われているか確認できます。

## 機能

- 一括クリーン（全対象アプリを強制停止 → 全対象アプリのキャッシュを削除）
- 一括終了（強制停止のみ）
- キャッシュクリーン（キャッシュ削除のみ）
- アイコン付きユーザーアプリ一覧と検索可能な保護設定
- ランチャー、電話、SMS、IME、時計、有効なユーザー補助サービスなどの自動保護
- DataStore によるユーザー保護設定と前回結果の永続化
- 失敗したアプリをスキップして続行する直列キュー
- `FLAG_STOPPED` による強制停止済みアプリの画面遷移前スキップ
- 強制停止後の確認ダイアログ／ボタン無効化の同時監視による待機短縮
- Android 15/16 AOSPでは解決確認済みのアプリ別ストレージIntentを優先し、旧OS／OEMではresource-id・ラベル・スクロール探索へフォールバック
- 各操作に対応する、透明背景・アイコンのみの Glance ホーム画面ウィジェット3種
- RAMの合計・使用中・利用可能量と、処理前後の参考値

## 必要な権限

- `BIND_ACCESSIBILITY_SERVICE`: ユーザーがAndroid設定から明示的に有効化します。設定画面上の操作にのみ使用します。
- `QUERY_ALL_PACKAGES`: ユーザーアプリ一覧と安全な除外対象を構築するために必要です。Google Playで配布する場合は、ポリシー上の許可用途と申告を事前に確認してください。
- `POST_NOTIFICATIONS`（Android 13以降、任意）: 現在の対象アプリと処理段階を通知します。拒否しても画面上の処理は動作します。
- `PACKAGE_USAGE_STATS`（任意の特殊アクセス）: 他アプリのキャッシュ容量を処理前に確認し、1 MB未満のアプリで設定画面を開かず高速にスキップするために使用します。ちょうど1 MB以上をキャッシュ削除対象とし、未許可や取得失敗時は従来の設定画面判定へ戻ります。

ネットワーク権限、ROOT、オーバーレイ権限は使用しません。

## ユーザー補助サービスを使う理由と初期設定

Android は通常アプリに、他アプリの強制停止やキャッシュ削除を直接行うAPIを提供していません。本アプリは、ユーザーに見えるAndroid設定画面を開き、ユーザー補助ノードを厳密に照合して同じ操作を自動化します。

1. アプリを起動します。
2. 「ユーザー補助設定を開く」を押します。
3. 「セーフクリーナー操作サービス」を選び、有効にします。
4. アプリへ戻り、操作サービスが「有効」と表示されることを確認します。

高速キャッシュ判定を利用する場合は、メイン画面の「使用状況へのアクセス設定を開く」から「セーフクリーナー」を許可します。この許可は高速化用であり、拒否した場合も一括処理は利用できます。

## ウィジェット

ホーム画面を長押しし、「ウィジェット」から次のいずれかを配置します。各ウィジェットは透明背景の1×1サイズで、表示は操作アイコンのみです。

- 一括クリーン（緑）
- 一括終了（赤）
- キャッシュクリーン（青）

それぞれ本体で押し直さず直接開始します。サービスが無効なら、本体の案内画面が開きます。旧版の3ボタンウィジェットを配置済みの場合は、更新後に旧ウィジェットを削除し、必要な新ウィジェットを配置し直してください。

## 安全設計

- 固定座標は使用しません。
- resource-id、厳密な表示テキスト／contentDescription、ノード構造の順に照合します。
- キャッシュ操作は「キャッシュを削除」と肯定的に特定できるノードだけを押します。
- 「データを削除」「ストレージを消去」等を候補にするロジックはありません。
- 不明な画面、無効なボタン、タイムアウトは誤操作せずスキップします。
- システムアプリを対象にせず、重要なユーザーアプリも自動保護します。

## ビルド

Android Studioでルートディレクトリを開くか、JDK 17以降とAndroid SDK 35を用意して次を実行します。

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

Windows版Gradleでプロジェクトの絶対パスに日本語が含まれる場合、JVMテストランナーがテストクラスを読めないことがあります。その場合はプロジェクトをASCII文字だけのパスに置くか、`subst` で一時ドライブへ割り当ててテストしてください。Androidアプリ本体のビルドには `android.overridePathCheck=true` を設定済みです。

### 端末へインストールするAPK

`dist/SafeCleaner-v1.2.9-install.apk` を使用してください。これはv1.2.8以前と同じ鍵で署名し、署名と整合性を確認済みの開発用APKです。既存版に上書きインストールできます。`app/build/outputs/apk/release/app-release-unsigned.apk` は未署名の中間成果物なので、そのまま端末へインストールできません。

v1.2.9では新しいAndroid・ColorOSのSettings画面で大量に発生するイベントの処理負荷を抑えました。強制停止後は `FLAG_STOPPED` に加え、対象画面の新しい更新でボタンが無効化された場合も完了と判定します。キャッシュ削除後の容量照会は250 msごとの連続実行をやめ、段階的に間隔を広げて端末負荷を減らしました。

v1.2.8では対象画面未確認・ボタン未検出・クリック不可・ボタン無効を区別し、クリック受付・処理完了・画面復帰を別々にログへ記録します。キャッシュ削除完了を確認できた場合、画面復帰が失敗しても削除成功を維持し、復帰警告を結果の詳細に表示します。結果画面は両操作のステータスと理由を併記します。

v1.2.7では設定画面未検出時の待機判定を修正しました。画面遷移後のSettingsイベントと対象パッケージ名／一意なアプリ名の一致を確認し、前のアプリ画面のボタンを操作しません。同名アプリをパッケージ名で識別できない画面は操作せず終了します。強制停止は対象パッケージの停止状態、キャッシュ削除は容量の減少・ゼロまたは削除ボタンの無効化で完了確認します。使用状況アクセスが未許可の場合、キャッシュ削除後もOEMがボタンを無効化しないと完了未確認になります。

## 動作ログの取得

初回だけ失敗するなど端末固有の症状を調査する場合は、PCでUSBデバッグを有効にして対象端末を接続し、次のコマンドで本アプリのログを保存します。

```powershell
adb logcat -c
adb logcat -v threadtime SafeCleaner:V '*:S' > safe-cleaner-log.txt
```

2行目を実行したまま、端末で「一括クリーン」を1回だけ実行して結果画面が出るまで待ち、PC側で `Ctrl+C` を押してください。作成された `safe-cleaner-log.txt` と、失敗タブに表示されたアプリ名・結果の画面キャプチャを提出してください。ログには対象アプリのパッケージ名と設定画面の状態が含まれるため、共有前に内容を確認してください。

## 現時点の制限

- 設定画面はAndroidバージョンやOEM、言語によって異なります。Android 15/16 AOSPではアプリ別ストレージ画面への解決可能なIntentを優先し、Android 8～14や非対応OEMでは日本語・英語の代表的なラベル、既知resource-id、安全なスクロールを使用します。未知のUIはスキップします。
- OEMが設定画面のノード情報を公開しない場合、ユーザー補助サービスでも操作できません。
- 強制停止済み、キャッシュが空、ボタンが無効な場合はスキップとして記録されることがあります。
- AndroidのバックグラウンドActivity起動制限やOEM独自制限により、ウィジェット起点の連続遷移が制限される端末があります。
- RAM差分はAndroid自身の回収・再起動・キャッシュ戦略で変動する参考値であり、解放量を保証しません。
- 実機OEMごとの最終確認は、対象端末での安全な動作テストが必要です。

## 構成

- `AppRepository` / `ExclusionRepository`: アプリ取得と自動・ユーザー除外
- `CacheStatsRepository`: 使用状況アクセスの確認とUID単位のキャッシュ容量事前取得
- `CleanerController`: 状態、二重起動防止、対象キュー、結果
- `CleanerAccessibilityService`: イベント監視と1件ずつの直列実行
- `SettingsNavigator` / `ForceStopHandler` / `CacheClearHandler`: 設定画面操作
- `OemUiResolver`: OEM差異を分離した安全な語彙とresource-id
- `widget`: Glanceウィジェットと直接実行入口
